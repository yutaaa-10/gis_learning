# 神奈川県の水インフラを地図で読み解く

## 1. コンセプト

上下水道は、浄水場や下水処理場に水を集めて処理し、長い管路網で各家庭とつなぐ**集中型**のインフラである。
人口が多く密集している地域では効率が良い。一方、人口が少なく施設から遠い地域では、管路が長くなるわりに使う人が少なく、維持が割高になる。人口が減っていけば、この差はさらに広がる。

このような地域では、建物や集落ごとに水を処理して循環させる**分散型**の水インフラが選択肢になる。

本プロジェクトの中心にある問いは次のとおり。

> **神奈川県で、分散型の水インフラを検討すべき地域はどこか？**

この問いに一度に答えるのではなく、**小さな問いを1つずつ立て、そのたびにGISの技術を1つ身につける**形で進める。

## 2. 目的

- 点・線・面・ラスタ・ネットワークという、GISの主なデータの型を一通り扱う。
- 各STEPを**QGISで確認し、Pythonで再現する**。両方を使える状態になる。
- 「分散型が必要な地域」を自分の基準で定義し、データで評価する経験を得る。

## 3. 範囲

| 区分 | STEP | 位置づけ |
|---|---|---|
| ノルマ | 1〜3 | 必ず完成させる。ここまでで成果物として成立する |
| 発展 | 4〜8 | 余力に応じて1つずつ進める |

対象地域は**神奈川県**とする。藤沢市の水道は神奈川県企業庁（県営水道）が運営していて、浄水場も市の外にあるため、市単位では施設の関係が見えにくいからである。藤沢市（用田を含む）は、県全体の中での位置づけとして確認する。

## 4. STEPの設計

各STEPは **問い → 使う技術 → 成果物 → 考えること** の順に設計する。

### STEP 1：神奈川県の浄水場・下水処理場はどこにある？（ノルマ）

- **使う技術**：データの取得と読み込み、属性の確認、CRSの確認と変換、複数レイヤーの重ね合わせ
- **データ**：国土数値情報「上水道関連施設」「下水道関連施設」「行政区域」（神奈川県）
- **成果物**：県の境界の上に、上水道施設と下水道施設を色分けして重ねた地図
- **考えること**
  - 施設の種類（浄水場・配水池・処理場・ポンプ場など）は属性のどの列で分かるか。コードの意味は仕様書で確認する。
  - データの基準年はいつか。現在も同じ施設があるか。
  - 施設が集まっている所、まばらな所はどこか。それはなぜか。

### STEP 2：市町村ごとに施設はいくつある？（ノルマ）

- **使う技術**：空間結合（spatial join）、グループ集計、属性の結合、塗り分け地図（コロプレス図）
- **成果物**：市町村別の施設数の表と、塗り分け地図
- **考えること**
  - 施設の属性にもともと市町村名があるなら、空間結合の結果と一致するか。食い違う場合、原因は何か。
  - 行政区域データは1つの市町村が複数のポリゴンに分かれていることがある。集計の前にどう扱うか。
  - 「施設数」だけで比べてよいか。面積や人口で割ると見え方はどう変わるか。

### STEP 3：各地点から一番近い施設はどこで、何km離れている？（ノルマ）

- **使う技術**：投影座標系への変換、最近傍探索（nearest join）、距離計算、空間インデックス
- **追加データ**：距離を測る「地点」として、地域メッシュ（e-Statの人口メッシュなど）または自作の格子
- **成果物**：各メッシュから最寄りの浄水場（または配水池）・下水処理場までの距離を色で表した地図
- **考えること**
  - 距離をメートルで正しく測るには、どのCRSを使うべきか（下の「6. 設計方針」を参照）。
  - メッシュの「位置」をどこにするか（中心点？ 重心？）。
  - 全メッシュと全施設の距離を総当たりで計算すると、計算量はどうなるか。空間インデックスはそれをどう減らすか。
  - 直線距離は実際の管路の長さとどれくらい違いそうか。

## 6. 設計方針

### CRS（座標参照系）

| 用途 | CRS | 理由 |
|---|---|---|
| 保存・表示 | 元データのCRS（JGD2011の緯度経度など） | 元データとの対応を保つ |
| 距離・面積の計算 | JGD2011 平面直角座標系 第IX系（EPSG:6677） | 神奈川県を含む系で、単位がメートル |

- 読み込んだら、まず `.crs` を確認する。
- 距離や面積を計算する前に、必ず投影座標系に変換する。緯度経度のまま計算すると、単位が「度」になり意味のない値になる。
- 複数のレイヤーを組み合わせる前に、CRSをそろえる。

### ディレクトリ構成

```
data/
  raw/          元データ（取得したままの状態。手を加えない）
  processed/    加工したデータ（スクリプトで再生成できるもの）
project/final_analysis/
  README.md     この設計書
  step01_facilities.py
  step02_count_by_city.py
  step03_nearest_distance.py
  outputs/      地図画像・集計表
```

- `raw` のデータは書き換えない。加工結果は必ず `processed` に別名で保存する。
- 各スクリプトは単独で実行でき、`raw` から結果まで再現できるようにする。
- ファイルパスはスクリプトの中にばらばらに書かず、冒頭の定数にまとめる。

## 7. 分析の限界

- 管路の実際の位置は公開されていないため、施設からの直線距離や道路距離で**代わりに推定**する。
- 国土数値情報の施設データは基準年が古い可能性がある。
- 施設の「近さ」は、実際の給水・処理の担当区域とは一致しない。配水系統は地形や歴史的経緯で決まっている。
- スコアが高い地域は「分散型の**検討の優先度が高い**」地域であり、「導入すべき」と断定はしない。

## 8. 結果と記録

### STEP 1：神奈川県の浄水場・下水処理場はどこにある？

**答え**
- 県の東部・湘南（藤沢市を含む）は、全域が大きな上水道の給水区域に入っている。
- 県西部・北西部の山間部（丹沢・宮ヶ瀬湖・道志川沿いなど）には、**給水区域の外**と**小さな簡易水道**が集中している。給水区域の外は、背景地図で見るとほぼ山地だった。
- 浄水場は「山あいの小規模な施設」と「相模川沿いの平地にある大規模な施設」に分かれる。
- 下水処理場は海沿いや川の下流（低い所）にあり、ポンプ場は箱根のような山がちな所や、海沿いの平らで低い所（重力で流しにくい所）に多い。**下水道の施設配置は地形（高低差）に強く影響されている**、というのが仮説。

**データの中身**

| レイヤ | 中身 | 件数 |
|---|---|---|
| P21a | 上水道の給水区域（面）。`P21A_003` 種別：1=上水道、2=簡易水道（公営）。神奈川県に 3（非公営）は無い | — |
| P21b | 浄水場など（配水池なども含む） | 63 |
| P22b | 下水処理場（「○○浄化センター」などの名前が多い） | 43 |
| P22a | 下水道のポンプ場 | 143 |

**方法**：QGISで表示（Pythonスクリプトは無し）。給水区域を `P21A_003` で色分けし、行政区域とOpenStreetMapの背景を重ねた。

**つまずいた点・学んだこと**
- P21には `.prj` が無く、QGISでCRSが不明（「？」マーク）になった。仕様書の「JGD2000 /（B, L）」から **EPSG:4612** を設定した。
- P22は `.cpg` が無く、日本語が文字化けする。エンコーディングに **Shift_JIS（cp932）** を指定する。
- レイヤの重なり順：上にあるレイヤほど手前に描かれる。背景地図は一番下に置く。
- 給水区域は「水を取る場所」ではなく、「水道事業者が**水を配っている範囲**」。
- 給水区域の外＝水道が無い、とは限らない。①人が住んでいない、②井戸や沢水で自給、③給水人口100人以下でデータに載らない小さな水道、④データに載っていないだけ、の可能性がある。

### STEP 2：市町村ごとに施設はいくつある？

**答え**
- 浄水場が多いのは、相模原市（11）、横浜市（7）、愛川町（6）など、**県の西部・北部の山側**の市町村。
- 下水処理場が多いのは、横浜市（13）、川崎市（5）、横須賀市（4）など、**東部・海沿いの都市**。
- 藤沢市は浄水場0・下水処理場2。水は市外から送られ、下水は市内で処理している。

**成果物**：`outputs/step02_count_by_city.png`

**方法**：[step02_count_by_city.py](step02_count_by_city.py)
1. P21は `set_crs("EPSG:4612")` でCRSを宣言してから、すべて `to_crs("EPSG:6677")` でそろえる
2. 行政区域は島などで1つの市町村が複数ポリゴンに分かれているため、`dissolve(by="N03_004")` で市町村ごとに1つにまとめる
3. `sjoin(predicate="within")` で各施設に市町村名を付け、`groupby().size()` で数え、`merge` で市町村に戻す（0件は `fillna(0)`）

**学んだこと**
- `set_crs` は「元のCRSはこれ」と宣言するだけで座標の数値は変えない。`to_crs` は座標を計算し直して変換する。
- QGISの「ポリゴン内の点の数」でも同じ集計ができる。Pythonにしておくと、データの更新や他の県にも同じ手順で使える（再現性）。

**残った謎**：浄水場の合計が **62 / 63** で、1件がどの市町村にも入らない。海岸線ぎりぎり・県外・境界の年次の違いのどれかと考えられる。`sjoin` を `how="left"` にすると特定できる。

### STEP 3：各地点から一番近い施設はどこで、何km離れている？

**答え**

| | 人が住むマスの平均 | 人口で重み付けした平均 | 一番遠いマス |
|---|---|---|---|
| 浄水場 | 5.7 km | 6.3 km | 28.9 km（三浦半島の先） |
| 下水処理場 | 5.1 km | 3.8 km | 24.9 km（丹沢の山あい） |

- **浄水場から一番遠いのは、山奥ではなく三浦半島**だった。人が多く住んでいるのに近くに浄水場が無く、遠くの浄水場から**長い水道管で水を運んでいる**。「遠い＝水道が無い」ではなく「遠い＝長い管に頼っている」と読むべきで、災害で管が切れたときに弱い地域の候補になる。
- **下水処理場から遠いのは丹沢・山北の山あい**で、STEP 1の「給水区域の外・簡易水道」の地域とほぼ重なる。分散型を検討すべき地域の有力な候補。
- 人口で重み付けすると下水処理場の平均距離が縮む。多くの人は処理場の近くに住み、遠いのは人が少ない場所。
- **用田**：最寄りの浄水場は綾瀬浄水場（3.1 km）、下水処理場は綾瀬終末処理場（4.0 km）。県の平均程度で、水道の面では不便な場所ではない。

**成果物**
- `outputs/step03_nearest_distance.png`
- `data/processed/step03_mesh_distance.gpkg`（マスごとの人口・最寄り施設・距離。QGISで開ける）

**方法**：[step03_nearest_distance.py](step03_nearest_distance.py)
1. 1次メッシュ4区画の3次メッシュを `pd.concat` でつなげる（22,300マス）
2. 県全体の形と重なるマスだけに絞る（`sjoin`, `intersects`）→ 2,603マス
3. 人口の表（見出し2行・Shift_JIS）を読み込み、`KEY_CODE` でメッシュと `merge`。秘匿値 `*` は欠損値にする
4. マスの中心点（`centroid`）から `sjoin_nearest` で最寄りの施設と距離を求める

**学んだこと**
- 1次メッシュ番号は「緯度×1.5」と「経度−100」。神奈川県は 5238・5239・5338・5339 の4区画にまたがる。
- e-Statのメッシュは陸地のマスだけが配られている。人口の表と形のデータは別々で、`KEY_CODE` でつなぐ。
- `sjoin` も `sjoin_nearest` も、内部で空間インデックス（R-tree）を使い、総当たりせずに候補を絞っている。

**限界**
- 距離は直線距離。実際の管の長さはもっと長い。
- 「一番近い施設」と、実際にそのマスに水を送っている施設は一致しない（配水系統は地形や経緯で決まる）。
- 県境にかかるマスは丸ごと数えているため、人口合計が約978万人と実際（約920万人）より多い。東京都側の人口が一部入っている。
- 施設データは2010年度時点、人口は2020年。
- 用田の位置はおおよその座標（`YODA_LONLAT`）で、地図での確認が必要。

### ノルマ（STEP 1〜3）を終えて

> 神奈川県では、**山間部（丹沢・山北・清川など）**が、上水道の給水区域の外・小規模な簡易水道・下水処理場から遠い、という条件が重なっており、**分散型の水インフラを検討する優先度が高い**。
> 一方、**三浦半島**は人口が多いのに浄水場から遠く、長い管路に依存している。平常時の効率とは別に、**災害時のバックアップ**という観点で分散型が意味を持つ可能性がある。

次の候補：給水区域の外に何人住んでいるか（給水区域とメッシュの重ね合わせ）、各施設が支える人口（発展STEP 4）、2050年の人口（発展STEP 5）。
